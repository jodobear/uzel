# FACT-010 — portable napplets and queryless INC

- **Claim:** Two independent, runtime-agnostic napplets can exchange the exact `napplet:profile/open` v1 payload through the pinned queryless NAP-INC implementation, while using only runtime-mediated identity and outbox APIs.
- **Source revision:** `napplet/naps@5ac0490461ca6fec2f0d2e45b4835cf9bc08de24`, released Napplet line locked in `compatibility.lock`, current validated Uzel pin `jodobear/nampplets@d533a63d519c14470f900323958509cdea1c6479`, and transitive `pablof7z/nmp@005dc2a5f12aa414961b313d05ebb021934e385c`.
- **Probe/command:** locked JS unit/build checks; released conformance-cli 0.2.16; `cargo +1.89.0 test -p napd --locked`; exact asset audit; canonical Fedora WebKit smoke; Debian Bookworm build smoke.
- **Observed result:** Both production napplets build as one `index.html`, have no Uzel/Tauri/napd or direct-network dependency, pass conformance 6/0/4 each, and reject malformed convention payloads. `profile-card` requests exactly one canonical kind-0 row from the NMP-backed provider, rejects timestamps outside JavaScript's Date range, retains the exact authored metadata JSON for literal-text display, and never selects or revives replaceable events. `follow-list` keeps the NMP-owned kind-3 order, starts author-bound canonical kind-0 queries in batches of at most eight filters, preserves validated rows from errored or incomplete partial results, and retries only unresolved authors. At most 32 adaptive retry queries can be created per refresh. A correlated result rejected by the 64-KiB trusted-shell projection becomes a bounded incomplete terminal result, allowing adaptive splitting without falsely classifying one oversized batch as a global outage; an actual transport failure opens the refresh circuit and rejects queued profile work. Pictures are requested only for visible rows through bounded individual NAP-RESOURCE calls. At most two profile queries and four picture requests run concurrently; viewport exit cancels matching queued work and aborts an active request, no more than 32 pending picture object URLs exist, successful URLs are revoked after decode, and decoded image sources are removed on exit then reloaded through NAP-RESOURCE on re-entry. Resolved buttons expose friendly names plus canonical pubkeys to assistive technology, and failed identity reloads remove stale rows after observer teardown. The hostile artifact receives its future live sentinel through the existing exact-principal, exact-session NAP-CONFIG path because its trusted-shell child executes at `about:srcdoc`, not the host URL. All three final signed fixtures verify through the pinned NMP runtime. The native harness delivers `inc.event` to `profile-card` with shell-owned sender `follow-list`.
- **Correction:** The Vite plugin sidecar is not a final launchable manifest because it has no signed source tag. The released deploy CLI owns final source-bearing event creation and signing. Direct queryless NAP-INC does not require an archetype tag or the unsupported NAP-INTENT surface.
- **Decision:** Reuse upstream build, deploy/sign, NAP, nampplets, and NMP behavior exactly. Keep the `hostile-egress` artifact as a signed Work 06 input; Work 03 proves its build, unit inventory, signature, and exact bytes, not full browser denial.
