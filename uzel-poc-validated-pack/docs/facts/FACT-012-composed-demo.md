# FACT-012 — bounded multi-surface composition

- **Claim:** One Linux Uzel window can mount two independently verified napplets and route their interaction through one daemon-owned nampplets/NMP runtime without giving either frame native authority or duplicating NMP state.
- **Classification:** verified fact
- **Exact source/pin:** `jodobear/nampplets@7eccdee76a1afcfc3ff026c8f41b0072a4601840`, including unchanged copied trusted-shell assets with SHA-256 `036a63361eafa0f7c997cad02cb1cb80351c0cab58e6d746bf95fc0680a24a14` and `4a90816305125b30fbeaa8ae3e64a992cab8f89734eabe7fa8adbee9f40bc8a4`; transitive `pablof7z/nmp@005dc2a5f12aa414961b313d05ebb021934e385c`.
- **Probe/command:** `pnpm check`; `pnpm test`; `pnpm test:conformance`; `pnpm lint`; `pnpm format:check`; explicit ignored live-NMP test; `pnpm smoke`; `pnpm smoke:fedora`, all through the pinned Nix development shell.
- **Observed result:** The daemon admits only its exact four-fixture catalog and at most four active fixtures. It verified profile-card aggregate `9ee2d7bf...` and follow-list aggregate `eaf4e565...`, created distinct persisted-generation surface tokens, served both artifacts through bounded transfers, completed two NAP-SHELL handshakes, and returned an authored `identity.getFollows.result` under real Fedora WebKitGTK/Weston. Runtime and daemon tests delivered queryless `napplet:profile/open` from follow-list to the installed profile-card handler with the runtime-owned sender. Ordinary responses remained source-scoped. The upstream host maps original `MessageEvent.source` objects to exact surface tokens and removes a previous frame mapping on same-ID remount. The shell supplies persisted orientation/ratio, directional focus, resize, per-pane fullscreen, public read identity selection, source/degradation status, and a bounded type-only developer log hidden in user mode.
- **Rejected assumptions:** A singleton trusted-shell global cannot safely compose two frames because remounting replaces its only mapping. Payload IDs cannot select the target surface. Uzel therefore uses the reviewed portable upstream multi-surface host and returns the runtime-authorized target from the daemon. The automated Fedora harness proves both real frames and responses, but does not synthesize a pointer click inside an opaque-origin nested frame; contract, runtime, and daemon tests prove that interaction seam.
- **Decision:** Keep one daemon, one `RuntimeController`, one NMP engine/store, one trusted top frame, and two sandboxed child frames. Keep fixture discovery closed and POC-only. Permit cross-surface routing only after upstream runtime INC authorization. Retain the signed hostile artifact and full browser denial matrix for Work 06.
