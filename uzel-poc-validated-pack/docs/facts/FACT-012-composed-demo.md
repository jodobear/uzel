# FACT-012 — bounded multi-surface composition

- **Claim:** One Linux Uzel window can mount two independently verified napplets and route their interaction through one daemon-owned nampplets/NMP runtime without giving either frame native authority or duplicating NMP state.
- **Classification:** verified fact
- **Exact source/pin:** Rust runtime `jodobear/nampplets@d533a63d519c14470f900323958509cdea1c6479`; unchanged portable shell assets from `jodobear/nampplets@fc68bce0a4793a8618445e234bcc91d69e8b96de` with SHA-256 `f1a648993468098398a9e46413f7ed3721e2e2fce706ed3452ba1d1f04210f4d` and `55c194631e7e90901dee151bdeb3cdbd93ea1576ed07bb2546d39c2b0ab590be`; transitive `pablof7z/nmp@005dc2a5f12aa414961b313d05ebb021934e385c`.
- **Probe/command:** `pnpm check`; `pnpm test`; `pnpm test:conformance`; `pnpm lint`; `pnpm format:check`; explicit ignored live identity and naddr tests; `pnpm smoke`; `pnpm smoke:linux`, all through the pinned Nix development shell.
- **Observed result:** The daemon admits only its exact four-fixture catalog and at most four active fixtures. It verified profile-card aggregate `7886ec2e...` and follow-list aggregate `8ececfd3...`, created distinct persisted-generation surface tokens, served both artifacts through bounded transfers, completed two NAP-SHELL handshakes, and returned an authored `identity.getFollows.result` under real Linux WebKitGTK/Weston. The new identity fixtures initially derived invalid non-v4 `nmp-artifact://` identifiers from aggregate prefixes; the trusted host correctly refused them before iframe creation. Their base URLs now use valid UUID-v4 identifiers, a Rust regression checks every fixture against the exact trusted-shell grammar, Chromium accepts both real shell preludes, and the Linux WebKit smoke reports three NAP-SHELL deliveries plus two child acceptance callbacks. Runtime and daemon tests delivered queryless `napplet:profile/open` from follow-list to the installed profile-card handler with the runtime-owned sender and exact topic correlation. Ordinary responses remained source-scoped. The upstream host maps original `MessageEvent.source` objects to exact surface tokens and removes a previous frame mapping on same-ID remount. The shell supplies persisted orientation/ratio with a true 42/58 fresh default, directional DOM focus with explicit Enter-to-iframe interaction, resize, per-pane fullscreen in both orientations, public read identity selection that stops the old sessions before launching fresh sessions and frames, source/degradation status, and a bounded type-only developer log hidden in user mode. Identity submission is disabled and fails closed until both initial or restarted frames have acknowledged `shell.init`, so it cannot race an in-flight fixture launch. Fresh sessions prevent late responses from an old frame colliding with request identifiers reset by a new prelude. Both old frame acknowledgement channels close before the first stop IPC await, and callbacks from non-current tokens are ignored, so old and new tokens cannot combine into a false ready count. Shell status enters the waiting state before either mount, counts each surface only after the captured child prelude acknowledges exact `shell.init` acceptance over a one-shot transferred `MessageChannel`, and does not overwrite a recorded handshake failure.
- **Rejected assumptions:** A singleton trusted-shell global cannot safely compose two frames because remounting replaces its only mapping. Payload IDs cannot select the target surface. Uzel therefore uses the reviewed portable upstream multi-surface host and returns the runtime-authorized target from the daemon. The automated Fedora harness proves both real frames and responses, but does not synthesize a pointer click inside an opaque-origin nested frame; contract, runtime, and daemon tests prove that interaction seam.
- **Decision:** Keep one daemon, one `RuntimeController`, one NMP engine/store, one trusted top frame, and two sandboxed child frames. Keep fixture discovery closed and POC-only. Permit cross-surface routing only after upstream runtime INC authorization. Retain the signed hostile artifact and full browser denial matrix for Work 06.
