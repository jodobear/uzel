# FACT-014 — public identity, resource, and naddr catalog flow

- **Claim:** The Linux POC can load the supplied public identity and a signed napplet coordinate without browser network authority or product-owned Nostr selection.
- **Classification:** verified fact
- **Exact source/pin:** `jodobear/nampplets@d533a63d519c14470f900323958509cdea1c6479`, including fork PRs [#2](https://github.com/jodobear/nampplets/pull/2), [#3](https://github.com/jodobear/nampplets/pull/3), and [#4](https://github.com/jodobear/nampplets/pull/4); `pablof7z/nmp@005dc2a5f12aa414961b313d05ebb021934e385c`; released NAP packages remain pinned by `compatibility.lock`.
- **Probe/command:** ignored live tests `public_identity_profile_follows_and_picture_cross_only_native_providers` and `public_naddr_reviews_confirms_and_launches_exact_single_file`; full locked workspace tests; strict Clippy; browser click tests with console inspection and screenshots.
- **Observed result:** `npub16c9a45p5dr6l3jzmrvgdh9m7xy994tatxd6sm7kmxaygkq4lertsfnacfm` decoded to `d60bdad03468f5f8c85b1b10db977e310a5aafab33750dfadb37488b02bfc8d7`. NMP returned a canonical named kind-0 profile and at least 100 unique direct follows. The profile's HTTPS image crossed the native NAP-RESOURCE provider and returned an image MIME plus non-trivial bytes; WebKit received only an object URL. Restart with no relay lanes returned the same cached profile. The signed Good Morning Protocol naddr resolved to the expected author, d-tag, event, and aggregate; exact bytes verified, required capability denial blocked install, approval installed and launched the frozen build, and closing stopped it. Repeated confirmation mapped the second launch to its newly created runtime session rather than an older matching exact build. Browser clicks proved synchronous mount refusal and asynchronous child environment rejection both stop the new session, restore the base workspace, and preserve base 2/2 readiness. A forced daemon stop failure keeps the loaded session tracked, keeps identity/catalog controls disabled, reports the cleanup failure, and permits an explicit successful retry; it never reports base readiness while cleanup is unknown. Superseding an active-profile request with a followed-profile request re-enables Refresh only when the newest request settles. While an arbitrary napplet is open, identity switching and a second catalog load are explicitly disabled so no surface remains attached to stale identity state. Browser console reported zero application errors (the development server alone returned an unrelated missing-favicon 404).
- **Ownership:** Uzel supplies bounded secure indexer/app relay lanes, public read-key selection, Linux HTTPS resource transport, UI review/consent, and daemon IPC. NMP owns relay subscriptions, reconnects, NIP-65 discovery, canonical replacement, persistence, and evidence. Nampplets owns NAP providers, permission review, catalog resolution, exact artifact verification, installation, and lifecycle.
- **Rejected assumptions:** `EXACT DOMAINS AVAILABLE` was not useful user language and was replaced with explicit unavailable capability names or `All requested capabilities ready`. A fallback relay is not an app-content lane. Relay hints in an naddr are resolution evidence, not caller-owned routing truth. Browser `img.src` must not receive the remote HTTPS URL; only NAP-RESOURCE-returned object URLs are admitted by the boundary scanner.
- **Limit:** the current Linux rasterizer returns a typed refusal for SVG. The tested supplied profile image is JPEG; this fact does not claim SVG rendering.
- **Revalidate when:** any nampplets/NMP/NAP pin, operator relay lane, resource transport policy, naddr resolver, permission flow, or trusted-shell boundary changes.
