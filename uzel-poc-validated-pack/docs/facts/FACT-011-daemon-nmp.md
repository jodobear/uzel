# FACT-011 — daemon-owned runtime and canonical NMP data

- **Claim:** The Linux shell can use one daemon-owned pinned runtime/NMP data plane through bounded private AF_UNIX operations, including a 96-KiB verified asset, canonical live profile/follow reads, and cache-first restart.
- **Classification:** verified fact
- **Exact source/pin:** validated successor `jodobear/nampplets@e539378ef735ce06651fd94b71e06f9ce757cb13`, transitively pinning unchanged `pablof7z/nmp@005dc2a5f12aa414961b313d05ebb021934e385c`; pinned-Nix `nak 0.20.1` for the disposable relay probe. Work 04 was first validated at predecessor `08ddb87a975dcc44c8826e4c9c7fa7cfe7f701bf` and reran after the exact repin.
- **Probe/command:** `cargo test -p napd --lib`; `cargo test -p napd live_nmp_refreshes_then_restarts_cache_first_without_a_second_cache -- --ignored`; `cargo test -p napd-protocol`; pinned `nix ... develop --command cargo check --workspace`.
- **Observed result:** One daemon-owned `RuntimeController` verified and launched the 96172-byte fixture, served it as ordered 2048-byte chunks under 4096-byte frames, rejected an out-of-order request, returned a typed bounded error for an oversized runtime envelope, durably advanced surface/transfer generations across daemon restart, and shut down cleanly without unlinking a replacement socket. Socket-parent and product-state symlinks were refused. Bind refuses a live daemon socket, rechecks device/inode before removing a proven-stale socket, refuses insecure existing parent permissions without changing them, and times out an incomplete client so a later request can proceed. Product-state replacement fsyncs the file and parent directory. Failed identity persistence restores the previous exact NMP installation when disk is unchanged; a post-replacement directory-sync failure retains the new in-memory state so it cannot invert the state already visible after restart. A signed local-relay fixture containing an older kind-0, its newer replacement, duplicate relay rows, and a direct-follow event returned only canonical Alice data and two unique follows through the existing identity provider. With the relay stopped, restart restored the public read key through NMP and returned the cached canonical profile from NMP redb. The final headless Fedora run used disposable runtime and data roots, matched the stable daemon readiness line, and completed the exact-build, NAP-SHELL, artifact-response, and child-native-isolation assertions.
- **Rejected assumptions:** NMP redb does not restore the active read identity at this pin; Uzel therefore persists the canonical public key as bounded product metadata. Profile-owned indexer/app preferences reject `ws://` before the engine allowlist; disposable loopback probes use NMP's fallback lane plus explicit `allowed_local_relay_hosts`, while normal profile preferences remain `wss://`.
- **Decision:** Keep NMP/redb as the only event/profile/follow store. Persist only version, mode, canonical read key, and last reserved surface generation outside upstream stores. Correlate provider responses by request ID so an asynchronous `identity.changed` push cannot satisfy another request. Treat the socket parent as caller-owned when it already exists: validate rather than mutate it, and probe a pre-existing socket before any unlink.
- **Affected documents/code:** `crates/napd-protocol`, `crates/napd`, `apps/uzel-napd`, `apps/uzel/src-tauri`, `docs/02-architecture.md`, `docs/03-provisional-design.md`, `reports/slice-04-preflight.md`.
- **Confidence:** high for the pinned Linux POC; revalidate on any runtime, NMP, protocol, or relay-configuration change.
