# FACT-011 — daemon-owned runtime and canonical NMP data

- **Claim:** The Linux shell can use one daemon-owned pinned runtime/NMP data plane through bounded private AF_UNIX operations, including a 96-KiB verified asset, canonical live profile/follow reads, and cache-first restart.
- **Classification:** verified fact
- **Exact source/pin:** `jodobear/nampplets@d533a63d519c14470f900323958509cdea1c6479`, transitively pinning `pablof7z/nmp@005dc2a5f12aa414961b313d05ebb021934e385c`. Work 04 was first validated at predecessor `08ddb87a975dcc44c8826e4c9c7fa7cfe7f701bf` and reran after each exact repin.
- **Probe/command:** `cargo test -p napd --lib`; `cargo test -p napd --locked public_identity_profile_follows_and_picture_cross_only_native_providers -- --ignored --nocapture`; `cargo test -p napd-protocol`; pinned `nix ... develop -c cargo check --workspace`.
- **Observed result:** One daemon-owned `RuntimeController` verified and launched the 96172-byte fixture, served it as ordered 2048-byte chunks under a 524288-byte frame ceiling, and proved that a 65536-byte inbound envelope still fits after worst-case JSON escaping and wrapper fields. Routed responses above 64 KiB now stream as ordered 256-KiB chunks without raising that frame ceiling; the client validates the same surface, exact offsets, total, completion, UTF-8, and the trusted shell's 100-MiB-plus-64-KiB aggregate limit. It rejected out-of-order and oversized transfers, made surface stop and review cancellation retries idempotent, capped pending reviews at four, exposed them in status for restart reconciliation, durably advanced surface/transfer generations across daemon restart, and shut down cleanly without unlinking a replacement socket. Socket-parent and product-state symlinks were refused. The public-live probe decoded the supplied npub to `d60bdad...c8d7`, obtained its canonical kind-0 and at least 100 direct follows through NMP, downloaded its HTTPS avatar only through NAP-RESOURCE, then reopened the same NMP store with every relay lane disabled and returned the cached profile. Product metadata restored the canonical active read key.
- **Rejected assumptions:** NMP redb does not restore the active read identity; Uzel therefore persists the canonical public key as bounded product metadata. A plaintext loopback relay assigned only to NMP's fallback lane does not provide generic `Public` profile/contact content: wire evidence showed only kind-10002 discovery requests. Secure operator app lanes provide public identity content; fallback remains a distinct NMP-owned lane.
- **Decision:** Keep NMP/redb as the only event/profile/follow store. Persist only version, mode, canonical read key, and last reserved surface generation outside upstream stores. Correlate provider responses by request ID so an asynchronous `identity.changed` push cannot satisfy another request. Treat the socket parent as caller-owned when it already exists: validate rather than mutate it, and probe a pre-existing socket before any unlink.
- **Affected documents/code:** `crates/napd-protocol`, `crates/napd`, `apps/uzel-napd`, `apps/uzel/src-tauri`, `docs/02-architecture.md`, `docs/03-provisional-design.md`, `reports/slice-04-preflight.md`.
- **Confidence:** high for the pinned Linux POC; revalidate on any runtime, NMP, protocol, or relay-configuration change.
